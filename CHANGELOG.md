# Changelog

All notable changes to this project are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- Stacks: any combination of reader, printer, env, eval and core rows as
  one monomorphised interpreter. `mal_traits::Row` attaches each row's
  `Implementation` to its type; `crates/mal/src/stack.rs` is now the single
  list of rows (registry, `mal` flags and component benchmarks all derive
  from it); the `matrix` feature compiles every combination; a `stacks`
  bench target and `cargo xtask bench --stacks SPEC` time whole stacks; the
  results page reports each combination's interaction (measured over the
  product of its single-row ratios); `tests/stacks.rs` checks every stack
  prints what `std` prints; `MAL_CONFORMANCE_STACKS` runs the mal suite on
  stacks. See `docs/src/stacks.md`, which also lists cross-component
  candidate crates.
- Environment row `rapidhash`.
- Comparison rows, each verified against the mal test suite and
  benchmarked: readers (std, nom, winnow, chumsky, pest, peg, lalrpop,
  logos, regex), printers (std, itoa, memchr, ufmt), environments (std,
  hashbrown, indexmap, rustc-hash, ahash, foldhash, imbl, rpds), the `std`
  evaluator and core namespace (stepA), and line editors (rustyline,
  reedline).
- `mal-types`, the shared `Rc`-based value type rows agree on, and
  `mal-testkit`, the unit checks every reader, printer and env row runs.
- The `mal` binary is a stepA interpreter assembled from rows, with
  `--<component> <name>` to swap one row in and `--read-print` for step1.
- Conformance tests: the upstream mal test suite (vendored) run against
  every row, checking each reaches exactly its claimed step; a test that
  `CrateRef` versions match `Cargo.lock`; a test that every reader agrees
  with `std` on the benchmark corpus.
- `mal_bench::corpus::PROGRAMS`, evaluation workloads; environment rows are
  also timed running them on the `std` evaluator.
- [Trait notes](docs/src/trait-notes.md): where the traits forced rows away
  from their crates' idioms, and the refinements proposed.
- Charts on the results page, generated by `cargo xtask report` from the
  same numbers as the tables: per component, each implementation's
  geometric-mean time relative to `std`, and a heatmap of that ratio per
  workload. Inline SVG that follows the site theme, no JavaScript.

- Cargo workspace with `mal-traits` (component traits, step and component
  vocabulary, `Implementation` metadata, REPL driver) and `mal` (the REPL
  binary with a dependency-free step0 baseline and `--list`).
- Documentation site scaffold: mdBook under `docs/` and oranda configuration.
- CI: format, clippy, test, docs, `cargo deny`, and the oranda site build.
- Benchmarking: `mal-bench` (fixed workloads and one generic Criterion
  benchmark per component trait), bench lists in `crates/mal/benches/`
  that visit every row in `crates/mal/src/stack.rs`, and `cargo xtask bench
  | report | compare` to record runs as `runs/<id>/results.json` and
  generate `docs/src/results.md` from the newest component run and the
  newest stack run. CI checks the page is current
  and runs the benchmarks once as a smoke test. First run recorded for the
  `echo` baseline.
- `Component::title()` for headings; `mal` now also exposes its baselines
  and registry as a library for the benchmarks.

### Changed

- `run_repl` accepts unsized interpreters (`Box<dyn Interpreter>`).
- `mal` with no arguments now starts the stepA interpreter rather than the
  step0 echo; `--eval echo` runs the echo.
