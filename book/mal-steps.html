Make-a-Lisp in Rust: a rosetta comparison

The Make-a-Lisp steps

The mal process guide builds the interpreter in eleven cumulative steps. Each has a test file in the mal repository, and mal_traits::Step names each one. The table shows which components a step first exercises, which is what decides where a new feature lands in this workspace.

stepnameaddscomponents exercised
0step0_replprompt, read a line, print it backline editor
1step1_read_printtokenising, parsing into values, printing themreader, printer
2step2_evalevaluating symbols and function callsevaluator
3step3_envdef!, let*, nested environmentsenv
4step4_if_fn_doif, do, fn*, the core namespaceevaluator, core
5step5_tcotail-call optimisationevaluator
6step6_fileread-string, slurp, eval, atoms, load-filecore, reader
7step7_quotequote, quasiquote, cons, concat, vecevaluator, reader
8step8_macrosdefmacro!, macro expansion, nth, first, restevaluator
9step9_trytry*/catch*, throw, apply, map, predicatesevaluator, core
AstepA_malreadline, metadata, *host-language*, self-hostingall

Because the steps are cumulative, a row that reaches step 8 has passed the tests for steps 0 through 8. The Step enum is ordered the same way, so Step::Macros > Step::Quoting.
